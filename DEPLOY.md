# Pushing and deploying Epic Sea Cargo

Two repos, because they hold two different things.

| repo | holds | visibility |
|---|---|---|
| source | the Frexus mirror, `build_site.py`, `brand_assets.py`, `export_site.py`, the page CSS | **private** — it contains the theme's own files |
| site | `dist/` only: 4 pages + the 92 assets they load, `Dockerfile`, `nginx.conf` | public is fine — this is the finished website |

`dist/` is regenerated by `python3 export_site.py` and verified from the inside before it is
written, so it is never edited by hand.

## 1. Source repo

```bash
cd epic-repo
git add -A
git commit -m "Static export: brand logo + palette, real content, builder and checker"
git remote add origin git@github.com:YOURNAME/epic-sea-cargo-src.git
git push -u origin main
```

**The existing repo matters more than the new one.** `BENETHNGOSWE/EPIC-SEA-CARGO` is
**public right now** and its one commit contains 277 theme and demo-media files plus a 1.3 MB
`wp-json` dump. Pushing does not change that history, so: make that repo **private** (Settings →
Danger Zone → Change visibility) or delete it. Making it private is enough for the ThemeForest
question; the files still need a bought licence before the *site* goes live.

## 2. Site repo (this is what Coolify builds)

```bash
cd epic-repo/dist
git init -b main
git add -A
git commit -m "Epic Sea Cargo — static site"
git remote add origin git@github.com:YOURNAME/epicseacargo.com.git
git push -u origin main
```

Coolify → New Resource → the public repo → **Build Pack: Dockerfile** → *Build context path* `.`
→ add the domain. If you would rather deploy from the source repo, point Coolify at it and set
the build context path to `dist` — then delete `dist/.git` first, since a nested repo confuses
`git add`.

## 3. DNS, in order

1. Cloudflare zone per domain, nameservers at your registrar.
2. `A  @  → <Contabo IP>` **proxied**; `A www → @`; delete any parking record.
3. SSL/TLS mode **Full (strict)**, Always Use HTTPS, HSTS once the cert is issued.
4. `TXT  _github-pages-challenge…` — not needed here; nothing but this box serves the site.
5. Mail stays on Zoho in its own zone: MX/SPF/DKIM/DMARC per the earlier plan.

## Before you push, these are still placeholders

| what | where it shows | one-line fix |
|---|---|---|
| phone `+255 700 000 000` | top bar, contact tiles, footer, CTA band (text only, not dialable) | `PHONE = "+255 7XX XXX XXX"` in `build_site.py` |
| social handles | both rows are omitted entirely | `SOCIAL = {"facebook": "https://…", "linkedin": "…"}` |
| photos | every card and banner is still the theme demo's image | replace `wp-content/uploads/2025/09…10` files, same names, then rebuild |
| `SITE` | canonicals, sitemap, `og:` URLs | already `https://epicseacargo.com`; change if the domain differs |

Then: `python3 build_site.py && python3 export_site.py && python3 check_pages.py`.

**Tokens:** the one pasted into this chat was never used and should be revoked
(github.com → Settings → Developer settings → Personal access tokens → Revoke). For a scoped
push, a *fine-grained* token limited to the one repository with **Contents: Read and write**,
and an expiry of 7 days, is enough.
